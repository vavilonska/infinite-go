# Infinite Go · 无限围棋

**一手棋，一个世界。保留过去，探索另一种下法。**

A local-first Go experiment with branching histories and exact weighted outcomes. By [vavilonska](https://github.com/vavilonska), Source-available under PolyForm Noncommercial 1.0.0.

> v0.1 prototype: 同屏双人 + 可信局域网房间 + 可选自托管 AI。不是公网对战平台，没有账号、云服务或内置 AI 模型。渲染与真实手机 / Wi-Fi 兼容性仍需设备验收，详见 [验证记录](docs/TESTING.md)。

## 开始玩

需要 Node.js 22 或更新版本。没有 npm 依赖，不需要 `npm install`。

```sh
git clone https://github.com/vavilonska/infinite-go.git
cd infinite-go
npm start
```

在电脑浏览器打开 `http://localhost:8000`，选择 **9 / 13 / 19 路**（默认 9），贴目默认 7.5。开局分叉权重门槛默认 **1/512**，可选 1/4、1/8、…、1/512、自定义 2 的负整数次幂，或不限制。

- 同屏：两个人共用页面，点位置预览，再点「确认落子」
- 局域网：点「创建房间」，另一设备打开主机的局域网地址，只有一个可加入房间时可直接点「加入」，多房间再输入六位房间码。创建者执黑，加入者执白。见 [局域网指南](docs/LAN.md)
- 完全离线同屏、不需要房间：可用 `python3 -m http.server 8000` 静态运行，或 `HOST=127.0.0.1 npm start` 仅监听本机（Windows 可用 PowerShell 设置 `$env:HOST='127.0.0.1'`）
- 不要直接双击 HTML：ES modules 需要本地 HTTP 服务
- 结束前「导出 JSON」。刷新同屏页面会丢失未导出棋局；局域网房间在主机内存中，关闭服务器即消失。导出不包含重连凭据

**不要把房间服务暴露到公网，也不要做路由端口转发。** HTTP 未加密，仅供可信家庭 / 朋友局域网；不会自动修改防火墙。

异地熟人可自行使用 ZeroTier 等虚拟局域网，见 [远程联机教程](docs/REMOTE-PLAY.md)。网页不直接集成 VPN，也不替你建立网络或修改安全设置。

## 怎么分叉

1. 每轮按照固定的时间线 ID 快照依次行动，每条活动叶最多行动一次
2. 到当前叶时，玩家可正常落子，也可用历史滑块回到该叶中「自己待行」的旧节点，选择不同落子
3. 旧叶完整历史不变；新叶是共同历史前缀 + 替代落子；旧新权重各变成原来的 **1/2**
4. 分叉消耗旧叶本轮的行动。旧叶的待行颜色不变；新叶由替代落子的对手待行，从下一轮加入
5. 新叶还可继续分叉，但父叶权重必须**严格大于开局门槛**；等于或低于门槛时只可正常续弈。门槛最严格为 1/4，最宽为「不限制」。例如 1/2 可拆成两个 1/4，门槛为 1/4 时这两个叶便不能再分
6. 「不限制」模式不设分支次数、数量、深度或权重上限；实际仍受内存与设备性能限制。自定义指数为 2 至 4096，门槛 = 1 / 2^指数，完全使用精确整数比较。规则在开局固定，导出保存保留；旧版未带门槛的保存按原来的不限制规则导入

同一完整历史前缀上的已有出边不能重复，包括普通落子已经形成的出边。局面相同但历史不同不会误合并。树形总览用真实历史前缀的分叉节点与终端叶表示结构；旧叶不是被错误地当成静止的内部节点。横轴按实际落子手数推进。支持节点选择、展开 / 折叠、拖动平移、滚轮和双指缩放。

## 正式胜负如何决定

- 每盘独立计算气和提子，禁自杀；**positional superko** 检查该分支完整继承历史中的全部棋盘局面，停一手例外
- 连续双方 pass 后进入计分，暂不能分叉
- 人类双方共同点击整块死子，使用中国式面积计分（活子 + 单色围住的空点 + 白贴目）；共享 / 无主空点不归任一方
- 任何死子改动清除双方确认。只有黑白都确认才结算，有争议可继续下，继续保留以前的 superko 历史
- 无自动死活裁判；双活、劫争等有争议时应续弈或双方协商，不把引擎判断伪装成正式裁决
- 最终把**实际已结算胜盘**的精确有理数权重相加，一方严格超过 **1/2** 即锁定整体胜利。余盘仍可完成；所有盘结束却无人过半，整体平局
- UI 同时显示「完成分支 / 总分支」和「已结算权重」，两者含义不同

权重存储为任意精度 `BigInt` 分数的十进制字符串，不依赖浮点数累加。百分比和 AI 图表只是近似展示。

## 可选 AI

页面提供双人、人机、机机三个入口。未连接兼容服务时，后两个入口禁用且图表为空。连接后可选择人类执黑 / 白，主动开始 / 暂停 AI 落子。

内含轻量 [KataGo 桥接与 provider 协议](docs/providers.md)，需要你自行安装 KataGo、取得兼容模型和配置。仓库不打包它们，不内置密钥。也可实现 `capabilities / analyze / generateMove / cancel` HTTP 协议连接自己的引擎。

- 首版 AI 仅推进当前叶，**不自动分叉**；AI 模式只在同屏游戏运行，局域网保持双方人类角色
- 分析包含完整历史、规则、贴目、请求 ID 和历史节点 ID；黑胜率视角明确
- 当前叶黑胜率和全局预计黑方胜负权重分别画趋势；全局为 `Σ(叶权重 × 黑胜率)`，已结算盘用真实 `1 / 0 / 0.5`
- **加权预测不是整场获胜概率，也不是正式比赛结果。** 陈旧 / 未返回分析明确标注，缺叶时不声称得到最新全局值
- 趋势最多显示最近 120 个分析状态采样点，不是连续每手都有数据
- 进入计分时 AI 暂停，仍需人类检查并确认；不宣称 Read19、云引擎或任意标准 GTP 服务已经适配。标准 GTP 没有统一胜率字段

## 开发与验证

```sh
npm test
```

核心纯 JS，无构建步骤。文件结构：

- `engine.js`：提子、superko、分叉、轮次、精确权重、计分、保存验证
- `app.js` / `index.html` / `style.css`：响应式 UI、落子预览、保存、房间客户端
- `tree.js`：共同历史前缀树及手势
- `server.js`：权威局域网房间，角色、重连、版本与非法动作验证
- `ai.js` / `providers.js`：可选 AI 模式与独立的预测展示
- `katago-bridge.js`：可选独立 KataGo analysis 进程桥接
- `test/`：Node 自带测试运行器

当前不含公网匹配、账户系统、排位、云存储、自动部署或生产级安全保证。欢迎围绕规则边界、移动端触摸体验、性能和更多合法 provider 提交 issue / pull request。
